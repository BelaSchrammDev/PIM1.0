Version 1.1d:

Fix:

- vanilla blueprint data checked against the game definitions of the Warfare 3 update
  (Content/Data/Blueprints.sbc):
  - pistols and rocket launchers had wrong item names (missing "Item"), their stock was never counted
  - flare gun, flare gun magazine, fireworks, canvas and datapad had outdated blueprint ids
    (renumbered by the game), they could not be activated
  - StoneOreToIngotBasic removed (no longer in the game)
- Deuterium Fusion Reactors mod: the data came from a workshop version that was deleted,
  now taken from the current mod 1259182705 (item DTFuelCapsule, component MagnetronComponent;
  the LCD key of the magnetron changed)
- Industrial Overhaul mod, checked against v1.7.8:
  - bauxite refinery blueprints output Ingot Aluminum
  - the interior turret magazine blueprint (POInteriorTurret_Mag_50rd) produces the
    Anti-Personnel Turret Magazine
- refinery blueprints with the same input keep their definition order (stable sort);
  before, the order depended on the unstable List.Sort
- duplicate Industrial Overhaul assembler blueprint removed
- the debug text grew forever without debug panel (now a StringBuilder, cleared every cycle)
- LCD cell cache (DisplayBox) grew forever, shortened texts were never found in the cache
- masses below 1 kg are shown in g (missing return)
- long names on LCDs are shortened exactly to the column width
- hint "cargo is full" never appeared (was checked after "heavy")
- autocrafting threshold line without '=' crashed the script
- several autocrafting LCDs with different thresholds reset each other every cycle
- StringBuilderExtended fixed
- Water Recycling System: grey water and clean water are put at the intended position of the
  input inventory (the position was not passed on to the transfer)
- a typo in a True/False option of the config (custom data) stopped the script at start,
  now the option keeps its value
- autocrafting: items with a max amount of 1 were never crafted (the threshold was rounded down
  to 0, it is rounded up now)
- removing a weapon with several ammo types from the PIM group only removed it from one of
  its ammo types
- stacking: an item that fits completely into one of its containers was not gathered there if it
  was in only two containers, with more containers the last stack was left behind
- assembler queue: if a blueprint at its max amount was in the queue twice, removing it deleted
  a wrong queue item or stopped the script
- storage containers, weapons and farms: the wanted amount of an item was compared with every
  stack separately. Two stacks of one item that cannot be merged (e.g. bottles) stopped the script
  if items were still missing; now the stacks are added up
- assemblers, hydroponics farms and reprocessors tagged with upper case letters, e.g. "(SMS)",
  were controlled by PIM but their blueprints were not activated for autocrafting
- refining LCD: the remaining time showed "Infinity years" or "NaN days" if the amount of ore
  did not change between two measurements, now "..."
- hint "please define cargo for Ammo" appeared although an (sms,armory) container was defined
  (also for containers of a single item, e.g. (sms,steelplate)): emptying assemblers and refinerys
  only checked the cargo of the item type
- the flare gun was put into the (sms,tools) container instead of the armory (its magazine already
  went to the armory)
- hints on the PB display: "please define cargo" stayed after the cargo was defined or the item was
  gone, and it flickered or disappeared if one item of a type had a cargo and another one had none
  (a hint that was set again after it had been cleared in the same cycle was lost)
- hint "please define cargo for Ammo" also names the armory: "...(sms,ammo) or ...(sms,armory)"
- removing the (sms) tag from a refinery left it as PIM had set it: conveyor system off, and switched
  off while empty. Now conveyor and power are switched on again (not for blocks PIM does not fill,
  e.g. incinerator), and its hints disappear from the PB display
- removing the (sms) tag from an assembler left it switched off if PIM had switched it off while
  idle (assemblers_off), now it is switched on again
- the hint "assembler is damaged" also appeared for assemblers without (sms) tag
- (sms,keep) was registered as a cargo of the type "Keep": a full keep container showed the hint
  "cargo Keep is full", and SMS got a cargo use line for "Keep"
- the hint "assembler cannot unload output items" was not updated while disassembling: it stayed
  from the last assembling, and the disassembled components that could not be unloaded were not reported
- refinerys were not filled by the ore priority: the list was sorted by the calculated priority only
  after a refinery was filled with an ore below 100 (before, in the order the ores were found), and
  lowering the priority after filling did not change the order, so all refinerys of a type got the
  same ore. Now the highest current priority is filled in first, the next refinerys take other ores
- a refinery was filled with several ores in one go if there was not enough of the first one, and
  then the priority of the wrong ore was lowered; with a higher prioritised ore waiting it was even
  emptied again for every further ore. Now one ore per filling, the next one follows when the
  refinery is nearly empty
- a higher prioritised ore emptied the refinery and filled it with the same ore again if that ore
  came first in the priority list
- refinerys took ore from refinerys without (sms) tag
- the priority of the current ores was not weighted with 1.5 if the second ore had a higher one
- only the third item was moved out of a refinery, not a fourth or more

Changes:

- rewrite WaterRecyclerManager
- the (sms,ammoprio) LCD was removed: weapons that accept several ammo types use them in the order
  of the accepted types; a type is used if there is at least one magazine per weapon in stock,
  otherwise the next one, otherwise any type that is in stock
- blueprint definitions moved from C# calls to data files: PIM1.0/BluePrintData/<Mod>.txt,
  load order and workshop ids in Mods.txt. The build generates BluePrintsClasses/Generated/BluePrintData.g.cs
  (one compact string per mod), about 4,000 characters less script
- blueprint code split into pure parts (no Sandbox/VRage types, testable) and *Ingame.cs parts
- blueprints are loaded by a startup job instead of in the constructor: BluePrintLoadJob (SequentialJob)
  with one BluePrintModJob per mod, one data entry per step, maximum instruction budget while loading
- MyDefinitionId of blueprints is created on first use, scrap item types on first use
- refinery blueprint duplicate check via HashSet instead of List.Find
- ConvertAutoCraftingName split into DeriveAutoCraftingType / DeriveAutoCraftingName, dead rules removed
  (no change of the generated names)
- RefreshType.Incinerator renamed to NoAutofill, Composter added: shows "cannot be filled by PIM" with (sms)
- the mod list of the config is taken from the blueprint data (order of Mods.txt)
- removed mod support: Sigma Draconis Core (deleted on Steam), HSR (discontinued),
  Industrial Overhaul Water (no blueprints anymore); HSR refinery type and name rule removed
- LCD pages (autocrafting, oreprio, refining): built with a StringBuilder, a panel is only read again
  if the player changed it and only written if the content changed
- LCD pages run as jobs (LcdPage: AutocraftingPage, OrePrioPage, RefiningPage) before the autocrafting,
  rendered in parts (header, one block per type) within the instruction budget; a panel changed by the
  player while it is rendered is not overwritten
- PB info: the status is built once per cycle, every run only adds the running sign;
  RunningSign simplified (no StringBuilder, tested); shows "starting..." instead of
  "Standby" until the first cycle is done
- LCD pages and debug panel: only panels of the same construct (subgrids via rotors/pistons, no docked ships)
- parsing and rendering of the LCD pages moved to LcdPages.cs (pure, testable); ore priorities of the
  oreprio LCDs are applied after every priority calculation
- Ingot.DeuteriumContainer renamed to Ingot.DTFuelCapsule
- unused Config.mods and mod name constants removed
- helper methods as extension methods, TypeDefinitions moved to its own file
- Instructions.readme only contains the news of the current version, older ones are in this file
- ItemTypesConverter (pure, tested; SE parts in ItemTypesConverterIngame.cs): container tags to
  InventoryManagerList keys and back (one table instead of a dictionary and a switch), cargo categories
  (Armory, Seeds, Food, Waste; the item lists in ItemCasts.cs), the cargo of an item (item, category,
  type) in one place instead of three, and the parts of an item id (TypeOf, SubtypeOf, ToPimId,
  ToItemType) instead of splitting the strings in many places
- SendItemByTypeAndSubtype merged into SendItemByType, which takes the PIM item id
- the hints "... found. you can define cargo for it" (stone, gravel, ice, water, ...) are hidden after
  5 minutes until the script restarts
- hints of the PB display are reported every cycle instead of being set and cleared: a hint is shown
  as long as it is reported, ViewManagerJob removes the others at the end of the cycle (SweepViews).
  ClearWarning and SetWarningByCondition removed; views and hints moved to StatusViews.cs (pure, tested)
- instruction budget: proportional control instead of steps of 100, so it settles within a few cycles
  (budget scaled by measured / target cycle length, 60% of the way, at most x0.7 / x1.6 per cycle,
  no change within 3.5 .. 4.5 s). The cycle length is counted in runs (game time) instead of
  DateTime.Now, so a low sim speed does not raise the budget; cycles with blueprint loading are not used
- networking between the scripts via IGC (Share/NetWorking, can be linked into other scripts, e.g. SMS):
  NetWorkingNode (pure, tested) and NetWorkingIgc (transport, read at the start of every run,
  no message callback). Handshake: "hello" at start, answered with "ack", then "alive"
  every 3 s; a script without message for 10 s is removed. Message: (protocol, type, body "key=value;...")
- master/standby: of several PIMs on the same construct the one with the lowest EntityId works, the
  others wait in standby (Update100) and take over when it is gone; replaces the unfinished detection
  in LoopManager. Standby shows the master on the PB display and runs only the LoopManager once per run,
  the first cycle after standby is not used for the instruction budget
- run arguments are matched by the command name, with or without brackets, e.g. "flushrefinerys_all()"
- PimVersion and PimCopyright merged, the version is also sent to the other scripts
- config (custom data): no introduction text and no "### Config ###" markers anymore, the whole custom
  data is read; old configs are read as before and written in the new form
- options collect_all_Ore, collect_all_Ingot and collect_all_Component removed: untagged containers and
  connectors are always emptied completely (all item types, before only ore, ingots and components).
  One InventoryClearingJob and one list, ClearInventory without type filter.
  Containers with (sms,keep) keep their items as before ((sms,storage) is not emptied either, but filled)

New:

  - Medkit and Powerkit
  - Warfare 3 ammo: Countermeasure Flares, Anti-Personnel Turret Magazine, Homing Missile,
    Torpedo, Light Torpedo, Heavy Torpedo and Armor Piercing Torpedo

    LargeRailgunAmmo, LargeRailgunAmmoDUAP, SmallRailgunAmmo)

    vanilla blueprint)

  (not generated, not proposed by the tool), e.g. the PlantAndCook composter recipes,
  the Industrial Overhaul disposal and starting recipes
- PIM1.0.BluePrintGenerator: converts the data files into BluePrintData.g.cs during the build,
  drops item and display names the script derives by itself, data errors are reported as file(line)
- PIM1.0.BluePrintTool: compares the data files with the .sbc files of the game and the workshop mods
  (check, update, new, scan, status, download), status and titles via the Steam Web API
- test project (MSTest) with CI: Parameter, StringBuilderExtended, Jobs, Filter, CargoUse, TypeDefinitions,
  InstructionBudget, blueprint golden snapshot over the full pipeline, generator, load job and tool,
  LCD pages golden snapshot and read-back tests, NetWorkingNode, NetWorkingParser.GetValue
- config option ShowNetwork (default off): the scripts of the network with their master on the PB display
  (only if there is more than this PB), scripts on other constructs (docked) show their grid name
- networking: hello/alive reach the connected constructs (connectors), only scripts on the same
  construct count for the master and may send messages
- hint on the PB display if a script on the network uses another network protocol
- the PB display is set up on the first start (text mode, left aligned, font size 0.45, padding, orange text)
