Version 1.1d:

Fix:

- vanilla blueprint data checked against the game definitions (Content/Data/Blueprints.sbc):
  - pistols and rocket launchers had wrong item names (missing "Item"), their stock was never counted
  - flare gun, flare gun magazine and fireworks had outdated blueprint ids
    (renumbered by the game to Position0050/0051/0060-0065), they could not be activated
  - StoneOreToIngotBasic removed (no longer in the game)
- Deuterium Fusion Reactors mod: the data came from a workshop version that was deleted,
  now taken from the current mod 1259182705 (item DTFuelCapsule, component MagnetronComponent;
  the LCD key of the magnetron changed)
- Industrial Overhaul mod: bauxite refinery blueprints output Ingot Aluminum
- refinery blueprints with the same input keep their definition order (stable sort);
  before, the order depended on the unstable List.Sort
- blueprint initialisation could only run once (curmod was left at "" after the first run)
- duplicate blueprint definitions removed (Sigma Draconis refinery, Industrial Overhaul assembler)
- debug Echo removed from GetPositionString (the method was removed later)
- the debug text grew forever without debug panel (now a StringBuilder, cleared every cycle)
- LCD cell cache (DisplayBox) grew forever, shortened texts were never found in the cache
- masses below 1 kg are shown in g (missing return)
- long names on LCDs are shortened exactly to the column width
- hint "cargo is full" never appeared (was checked after "heavy")
- autocrafting threshold line without '=' crashed the script
- several autocrafting LCDs with different thresholds reset each other every cycle
- StringBuilderExtended fixed
- stacking only ran for components, ore and ingots were never stacked; every stacking cycle now
  runs one strategy on one item type (all strategies on components, then ore, then ingots)
- run argument "flushrefinerys_all" never worked, and unknown arguments without brackets
  were ignored silently instead of being reported as "unknown command"
- Water Recycling System: grey water and clean water are put at the intended position of the
  input inventory (the position was not passed on to the transfer)
- refining LCD: the number of refinerys was counted for the first ore a refinery ever had
  instead of the ore it is refining now
- possible script stop "divide by zero" when a refinery was filled with an ore that no refinery
  was refining yet
- a typo in a True/False option of the config (custom data) stopped the script at start,
  now the option keeps its value
- the hint "refinery is damaged" stayed on the PB display after the refinery was repaired
- autocrafting: items with a max amount of 1 were never crafted (the threshold was rounded down
  to 0, it is rounded up now), and nothing was queued if fewer items were missing than there
  are assemblers for them
- weapons that accept several ammo types were never loaded (the priorities came from the
  ammoprio LCD that was removed). Without configuration the first accepted type is preferred;
  a type is used if there is at least one magazine per weapon in stock, otherwise the next one
- removing a weapon with several ammo types from the PIM group only removed it from one of
  its ammo types
- stacking: an item that fits completely into one of its containers was not gathered there if it
  was in only two containers, with more containers the last stack was left behind
- stacking: exchanging the contents of two containers (item in exactly two containers) is
  repeated until it is finished, at most 10 rounds; before, the number of rounds depended on
  the number of other items
- assembler queue: if a blueprint at its max amount was in the queue twice, removing it deleted
  a wrong queue item or stopped the script
- ore and ingots inside refinerys were counted twice (by the grid scan and again by the
  refinery), which distorted the stock on the LCDs and the ore priorities
- storage containers, weapons and farms: the wanted amount of an item was compared with every
  stack separately. Two stacks of one item that cannot be merged (e.g. bottles) stopped the script
  if items were still missing; now the stacks are added up
- assemblers, hydroponics farms and reprocessors tagged with upper case letters, e.g. "(SMS)",
  were controlled by PIM but their blueprints were not activated for autocrafting
- refining LCD: the remaining time showed "Infinity years" or "NaN days" if the amount of ore
  did not change between two measurements, now "..."

Changes:

- rewrite WaterRecyclerManager
- blueprint definitions moved from C# calls to data files: PIM1.0/BluePrintData/<Mod>.txt,
  load order and workshop ids in Mods.txt. The build generates BluePrintsClasses/Generated/BluePrintData.g.cs
  (one compact string per mod), about 4,000 characters less script
- blueprint code split into pure parts (no Sandbox/VRage types, testable) and *Ingame.cs parts
- blueprints are loaded by a startup job instead of in the constructor: BluePrintLoadJob (SequentialJob)
  with one BluePrintModJob per mod, one data entry per step, maximum instruction budget while loading
- MyDefinitionId of blueprints is created on first use, scrap item types on first use
- refinery blueprint duplicate check via HashSet instead of List.Find
- ConvertAutoCraftingName split into DeriveAutoCraftingType / DeriveAutoCraftingName, dead rules removed
  (no change of the generated names)
- RefreshType.Incinerator renamed to NoAutofill, Composter added: shows "cannot filled by PIM" with (sms)
- the mod list of the config is taken from the blueprint data (order of Mods.txt)
- removed mod support: Sigma Draconis Core (deleted on Steam), HSR (discontinued),
  Industrial Overhaul Water (no blueprints anymore); HSR refinery type and name rule removed
- LCD pages (autocrafting, oreprio, refining): built with a StringBuilder, a panel is only read again
  if the player changed it and only written if the content changed
- LCD pages run as jobs (LcdPage: AutocraftingPage, OrePrioPage, RefiningPage) before the autocrafting,
  rendered in parts (header, one block per type) within the instruction budget; a panel changed by the
  player while it is rendered is not overwritten
- PB info: the status is built once per cycle, every run only adds the running sign;
  RunningSign simplified (no Tools base, no StringBuilder, tested); shows "starting..." instead of
  "Standby" until the first cycle is done
- LCD pages and debug panel: only panels of the same construct (subgrids via rotors/pistons, no docked ships)
- parsing and rendering of the LCD pages moved to LcdPages.cs (pure, testable); ore priorities of the
  oreprio LCDs are applied after every priority calculation
- Ingot.DeuteriumContainer renamed to Ingot.DTFuelCapsule
- unused Config.mods and mod name constants removed
- Tools.* helpers replaced by extension methods, TypeDefinitions moved to its own file
- Instructions.readme only contains the news of the current version, older ones are in this file

New:

- vanilla: Medkit and Powerkit
- PlantAndCook: EmptyTinCan; DailyNeedsSurvival: CleanToCleanWater
- Industrial Overhaul: base ammo (POHEMissile200mm, AutocannonClip, MediumCalibreAmmo, LargeCalibreAmmo,
  LargeRailgunAmmo, LargeRailgunAmmoDUAP, SmallRailgunAmmo)
- [Ignore] section in the data files: blueprints that are deliberately not used
  (not generated, not proposed by the tool), e.g. the PlantAndCook composter recipes,
  the Industrial Overhaul disposal and starting recipes
- PIM1.0.BluePrintGenerator: converts the data files into BluePrintData.g.cs during the build,
  drops item and display names the script derives by itself, data errors are reported as file(line)
- PIM1.0.BluePrintTool: compares the data files with the .sbc files of the game and the workshop mods
  (check, update, new, scan, status, download), status and titles via the Steam Web API
- test project (MSTest) with CI: Parameter, StringBuilderExtended, Jobs, Filter, CargoUse, TypeDefinitions,
  InstructionBudget, blueprint golden snapshot over the full pipeline, generator, load job and tool,
  LCD pages golden snapshot and read-back tests
